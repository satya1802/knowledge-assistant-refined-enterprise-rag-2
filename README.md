# Knowledge Assistant Refined Enterprise RAG (2)

Knowledge Assistant Refined Enterprise RAG Chatbot - Gemini-Only Persistent Knowledge Base Build Specification AI Provider Google Gemini API only Primary Source Persisted uploaded Knowledge Base Fallback Gemini general knowledge only after Knowledge Base retrieval finds no relevant match Persistence Documents, files, chunks, embeddings, users, chats and settings survive reloads/restarts Admin Login satya.ganaraju@quorq.ai Reference Stack FastAPI + React/TypeScript + SQLite local / PostgreSQL + pgvector production Core rule: Upload once, persist permanently until explicit deletion, index the document, and search the persisted Knowledge Base before every knowledge answer. Page refresh, logout/login, browser reopen, backend restart, or normal application restart must not erase uploaded documents or chat history. 1. Product Goal Build an enterprise RAG chatbot called Knowledge Assistant. Authorized users upload company documents into a shared Knowledge Base. The application permanently stores the uploaded file and its database records, processes and indexes it, and then uses that indexed content as the first source for chatbot answers. Google Gemini is the only AI provider. Do not configure, request, install, reference, or fall back to Groq or any Groq API key, model, SDK, embedding provider, environment variable, or integration. 2. Mandatory Admin Credentials Create/seed the following administrator account for the MVP: Username / Email: satya.ganaraju@quorq.ai Initial Password: admin@123 Role: Administrator Store the password as a bcrypt hash in the database; never store or log the plaintext password. The plaintext value above is only the required initial login credential. The user must be able to change the password after sign-in. 3. Gemini API Configuration - Only Use a Google Gemini API key only. Store it server-side in a gitignored backend/.env file or a secure runtime secret. Never expose it to React/browser code and never log it.

Generated by the Quorq AI SDLC platform. Two applications, one repository:

- **`frontend/`** -- the approved app design as a Vite + React SPA. Every screen
  was reviewed and approved, and runs on seeded sample data.
- **`backend/`** -- a FastAPI service. No architecture had been approved
  when this repository was created, so it starts with its health check and
  nothing else.

## Running it

```bash
cd frontend
npm install
npm run dev
npm test          # unit tests (Vitest)
npm run lint       # ESLint
npm run format     # Prettier
```

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload
pytest
ruff check .
ruff format .
```
